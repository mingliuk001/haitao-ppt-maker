# 海涛 PPT 制作

你负责「想内容」，本技能的程序负责「排版」。你只写一个内容文件（JSON），程序会按风格排好版，输出 .pptx 和 .html 两个文件。
**不要自己写代码画 PPT，不要用别的 PPT 工具，不要 npm install 任何东西**——本技能自带全部依赖。

## 三条底线

1. **事实只来自用户给的材料。** 数字、日期、人名、单位、指标，一个都不许自己编。正文里要用到、材料里又没有的事实，写成「【待补：缺什么】」，最后列出来告诉用户。封面的单位、汇报人、日期这类可选信息，材料里没有就直接不写，不要写【待补】。
2. **每页标题写成一句结论**，不写成话题。写「运维成本连续三年下降」，不写「运维成本情况」。
3. **先给用户看大纲，确认后再做。** 不要一口气直接出文件。

## 第一步　问清楚（缺什么问什么，已经有的不要再问）

- 做什么用、给谁看（领导汇报 / 客户提案 / 培训授课 / 发布会……）
- 材料在哪（用户贴的文字、上传的 Word/PPT、或只给了主题）
- 大约多少页（没说就按 10～15 页）
- 用哪套风格（用户没说，就按下表推荐一套并说明理由，让用户确认）
- 要哪种文件：pptx、html，还是两种都要（没说就两种都出）
- 要不要每页的口播备注（讲课、汇报时照着讲）；用户没提就不加

| 风格 | 写法 | 适合 |
|---|---|---|
| 政务红 | `zhengwu` | 机关单位、国企、党建、年度工作汇报、述职 |
| 商务咨询蓝 | `zixun` | 方案汇报、经营分析、项目提案、决策材料 |
| 科技暗黑 | `keji` | AI 与数字化、产品发布、技术分享、路演（HTML 动效最酷） |
| 杂志墨水 | `zazhi` | 观点分享、读书会、品牌故事、内刊、个人演讲 |
| 清新活力 | `qingxin` | 培训课件、活动策划、HR 与校园、面向年轻人 |
| 新中式 | `guochao` | 文化宣传、文旅、传统节日、非遗与地方特色 |

用户指定了风格就照用。如果和场合明显不搭（比如给机关领导汇报用清新活力），可以提醒一句并推荐更合适的，但用户坚持就照做。

**用户给的是 Word 或旧 PPT 文件时**，先用本技能的提取工具读出文字：

```
<node> <本技能目录>/scripts/extract.js <文件路径>
```

`<node>`：在 WorkBuddy 里，指它托管的 Node 程序的完整路径（系统提示里给出了，不要直接写 node）；在其他智能体里，直接写 `node`。旧版 .doc/.ppt 请用户先在 WPS 里另存为 .docx/.pptx。

## 第二步　出大纲，等用户确认

用一张表列出每一页：页码、页型、标题（一句结论）、这一页放什么。页型从下面 12 种里选，**相邻两页尽量不要用同一种页型**，有数字就用 kpi 或 chart，有步骤就用 process，有时间就用 timeline。

| 页型 | 用途 |
|---|---|
| cover | 封面（第一页） |
| toc | 目录（自动按章节生成，不用写内容） |
| section | 章节页（每章开头） |
| points | 2～6 条要点 |
| kpi | 2～4 个关键数字 |
| chart | 柱状图 / 折线图 / 饼图 + 右侧结论 |
| compare | 左右对比（现状 vs 目标、问题 vs 对策） |
| timeline | 3～6 个时间节点 |
| process | 3～5 个步骤 |
| table | 表格（最多 5 列 7 行） |
| statement | 一句金句，单独一页 |
| ending | 结束页（最后一页） |

把大纲发给用户，**停下来等他说「可以」或提修改意见**，改完再进入下一步。只有用户事先明确说了「不用确认、直接做」，才可以跳过这一步。

章节（section）少于 2 个时不要放目录页。

## 第三步　写内容文件

按 `references/content-guide.md` 的格式和字数上限写一个 JSON 文件，存到用户的工作目录，文件名用 PPT 的标题。写之前务必读一遍 content-guide.md，里面有每种页型的写法、字数上限和完整示例。

要点：
- 严格按字数上限写。字数超了，程序会报「放不下」，还得返工。
- 图表的数值只写数字（`1280`，不写 `"1280万元"`），单位写在 `unit` 里。
- 需要口播备注时，每页加 `"notes": "……"`，写成能直接念的口语。

## 第四步　生成文件

```
<node> <本技能目录>/scripts/build.js <内容文件.json> --style <风格写法> --out <输出目录>
```

- 只要 pptx 就加 `--format pptx`，只要 html 就加 `--format html`，不加就两种都出。
- 程序结束时看退出码和提示：
  - **0**：成功。
  - **2**：文件已生成，但有文字放不下。提示会写明「第几页第几条，请缩短到约多少字」。照着改 JSON，再运行一遍，直到不再报问题。不许跳过，也不许改小字号去硬塞。
  - **1**：内容格式错了。按提示改 JSON 后重跑。
- 想先检查不出文件，可以加 `--check`。

## 第五步　交付

告诉用户：
1. 两个文件的位置。
2. pptx 用 WPS 或 PowerPoint 打开就能改字；图表双击可以改数据。
3. html 用浏览器打开：方向键或翻页笔翻页，按 F 全屏，动效自动播放；想要 PDF，就在浏览器里打印，选「另存为 PDF」。
4. 列出所有「【待补】」的地方，请用户补齐。
5. 换风格只需要改 `--style` 重新生成，内容不用重写。

## 常见情况

- **用户只给了一个主题、没有材料**：可以帮他搭结构、写观点性的文字，但所有数字和事实都写「【待补】」，并在交付时说明。
- **页数很多**：一章 3～5 页为宜，超过 20 页建议拆成两份。
- **用户要改某一页**：只改 JSON 里那一页，然后重新生成。不要动其他页。
- **用户自己在 pptx 里改过字**：再次生成会覆盖他的修改。重新生成前先提醒他，或者换一个文件名输出（加 `--name 新文件名`）。
