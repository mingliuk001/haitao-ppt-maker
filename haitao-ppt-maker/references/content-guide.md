# 内容文件写法

内容文件是一个 JSON。程序只认下面这些字段，多写的会被忽略，写错的会报错。
完整示例见同目录的 `example.json`（13 页，12 种页型都用到了），照着它的样子写最稳妥。

**字数怎么算**：一个汉字或一个中文标点算 1 个字；英文单词和数字算半个字。表里的上限在六套风格上都实测放得下，**不要超**。

## 全稿信息（放在最外层）

```json
{
  "title": "2026年数字化转型工作汇报",
  "subtitle": "以数据驱动管理提效，推动业务全面上云",
  "org": "某某集团信息中心",
  "author": "汇报人：张三",
  "date": "2026年10月",
  "style": "zhengwu",
  "slides": [ ...每一页... ]
}
```

| 字段 | 必填 | 上限 | 说明 |
|---|---|---|---|
| title | 是 | 24 字 | 封面大标题。超过 12 字时，用 `\n` 指定换行位置，免得把一个词拆到两行，如 `"AI赋能办公实战\n培训需求分析"` |
| subtitle | 否 | 26 字 | 封面副标题 |
| org | 否 | 18 字 | 单位名称，会出现在封面和页脚 |
| author | 否 | 12 字 | 如「汇报人：张三」 |
| date | 否 | — | 如「2026年10月」；新中式风格会据此在封面印章上写年份干支 |
| style | 否 | — | 风格写法；命令行的 `--style` 优先 |

每一页都可以加 `"notes": "口播备注"`，长度不限，会写进 pptx 的备注栏。

## 12 种页型

### cover　封面
```json
{ "type": "cover" }
```
内容自动取全稿的 title、subtitle、org、author、date。

### toc　目录
```json
{ "type": "toc" }
```
自动列出所有 section 页的标题。全稿最多 6 个章节；少于 2 个章节时不要放目录页。

### section　章节页
```json
{ "type": "section", "title": "年度工作成效", "sub": "四项核心指标全部超额完成" }
```
title 不超过 12 字；sub 不超过 24 字（可省略）。章节号自动编。

### points　要点
```json
{ "type": "points", "title": "今年做对了四件事",
  "items": [
    { "title": "先打通数据", "text": "建成集团统一数据平台，34 个系统的数据第一次能在一张表里查到" },
    { "title": "小步快跑上场景", "text": "每个场景先在一个部门试 30 天，跑通了再推广" }
  ] }
```
- items 2～6 条；每条的 title 不超过 10 字。
- text 上限看条数：2 条时 70 字，3～4 条时 44 字，5～6 条时 30 字。

### kpi　关键数字
```json
{ "type": "kpi", "title": "四项核心指标全部超额完成年度目标",
  "items": [
    { "value": "98.6", "unit": "%", "label": "业务系统上云率", "note": "年初目标 90%" },
    { "value": "1,280", "unit": "万元", "label": "年度节约运维成本", "note": "同比下降 23%" }
  ] }
```
- items 2～4 个。
- value 只写数字，最多 6 个字符（如 `1,280`、`98.6`）；unit 不超过 3 字；label 不超过 8 字；note 不超过 14 字（可省略）。
- value 是纯数字时，HTML 版会有数字滚动的动画。

### chart　图表
```json
{ "type": "chart", "title": "运维成本连续三年下降，今年降幅最大",
  "chart": {
    "kind": "bar",
    "categories": ["2022", "2023", "2024", "2025", "2026"],
    "series": [ { "name": "运维成本", "values": [2350, 2210, 1960, 1660, 1280] } ],
    "unit": "万元",
    "highlight": 4
  },
  "takeaways": ["2026 年运维成本 1280 万元，比 2022 年少了近一半", "主要来自服务器整合和老旧系统下线"] }
```
- kind：`bar` 柱状图、`line` 折线图、`pie` 饼图、`doughnut` 环形图。
- categories 最多 8 个，每个不超过 5 字。
- series 是数据组：柱状图和折线图最多 3 组，饼图只能 1 组。**values 只写数字**，个数必须和 categories 一样多。
- unit：单位，显示在图表下方。
- highlight：可选，要突出显示第几根柱子（从 0 数起）。只有 1 组数据的柱状图才生效。
- takeaways：右侧结论，最多 3 条，每条不超过 30 字。第一条会加粗，写最重要的结论。不写就是整页大图。

### compare　左右对比
```json
{ "type": "compare", "title": "从「能用」到「好用」，要补三块短板",
  "left":  { "title": "现在：能用", "items": ["系统上了，但很多人还是习惯线下填表", "数据能查，但要找信息中心导出"] },
  "right": { "title": "明年：好用", "items": ["手机上就能办完 80% 的日常审批", "业务人员自己拖拽出报表"] } }
```
左边放「现状 / 问题 / 过去」，右边放「目标 / 对策 / 现在」，右边会用主色突出。每边 title 不超过 10 字，items 最多 5 条，每条不超过 22 字。

### timeline　时间线
```json
{ "type": "timeline", "title": "2027 年分四个阶段推进",
  "items": [
    { "time": "Q1", "title": "摸底与规划", "text": "梳理全部业务流程，确定第二批场景清单" },
    { "time": "Q2", "title": "平台升级", "text": "数据平台扩容，接入生产一线设备数据" }
  ] }
```
items 3～6 个；time 不超过 7 字；title 不超过 7 字；text 在 3～4 个节点时不超过 26 字，5～6 个节点时不超过 16 字。

### process　流程步骤
```json
{ "type": "process", "title": "新场景上线统一走五步",
  "items": [
    { "title": "业务出题", "text": "业务部门写清楚要解决什么问题" },
    { "title": "评估立项", "text": "信息中心评估投入产出，两周内答复" }
  ] }
```
items 3～5 步。3～4 步时 title 不超过 8 字、text 不超过 30 字；5 步时 title 不超过 6 字、text 不超过 22 字。最后一步会用主色突出。

### table　表格
```json
{ "type": "table", "title": "2027 年重点项目与预算",
  "header": ["项目", "牵头部门", "完成时间", "预算（万元）"],
  "rows": [ ["数据平台扩容", "信息中心", "2027年6月", "320"], ["移动办公升级", "办公室", "2027年4月", "150"] ] }
```
最多 5 列、7 行；每格不超过 8 字（列少时每格可以多写几个字，程序会量，放不下会提示）。每行的格数必须和表头一样。第一列会加粗。行多了就拆成两页。

### statement　金句
```json
{ "type": "statement", "text": "数字化不是买系统，而是让每个人每天少做一件重复的事。", "source": "集团数字化工作会议" }
```
text 不超过 40 字，中间最好有一个逗号（程序会优先在逗号处换行；也可以用 `\n` 自己指定）；source 不超过 16 字（可省略）。

### ending　结束页
```json
{ "type": "ending", "title": "谢谢", "sub": "敬请各位领导批评指正" }
```
title 不超过 8 字；sub 不超过 20 字。

## 写好一份的经验

- 一章 3～5 页；全稿 10～15 页最常见。
- 开头 cover → toc → 第一个 section；结尾放一页 statement 再接 ending，收得住。
- 有对比的数字（今年 vs 去年、目标 vs 实际），优先用 kpi 的 note 或 chart 的 highlight 表达，不要只罗列。
- 只有两列的数据（如「方向 / 人数」），用柱状图比用表格好看。
- 同一份内容可以换六套风格出，内容文件不用改。
